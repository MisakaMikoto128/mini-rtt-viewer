# Mini RTT Viewer 瘦身与界面整改设计

日期：2026-10-28  
状态：用户已批准按 2026-10-28 审查结论实施

## 目标

在不改变 RTT 数据面行为、不引入前端框架或 npm 构建链的前提下，删除可再生垃圾和无引用代码，拆分 `web.rs` 与前端单文件，统一状态来源，并重排连接、日志、发送和状态区域。

## 非目标

- 不重写 J-Link DLL 连接序列、FFI 绑定、worker 生命周期门闩或 ANSI/断行算法。
- 不修改或合并 probe-rs 实验分支。
- 不引入 React、Vue、Slint、npm、打包器或新的运行时依赖。
- 不增加局域网鉴权，不改变已声明的安全口径。
- 不为了实现“窗口几何记忆、第二实例唤起、托盘连接控制”等独立 backlog 新功能而扩大本次范围。

## 实施边界

### 1. 仓库瘦身

只删除 `target*` 构建目录、Python 缓存、临时截图和其他可再生构建产物。删除前逐项核对路径与 Git 跟踪状态；保留 `assets/`、`themes/`、`docs/images/`、源码示例及测试。不得删除用户偏好文件或 J-Link 安装内容。

### 2. 工程基线

修复 rustfmt 与 Clippy 门禁；CI 运行完整 `tests/web`，而不是只运行 `test_spec.py`。先修复已登记的暂停刷新状态问题，再补回归测试。

### 3. Rust 模块化

保留 `web` 的公开入口和路由契约，将共享状态、HTTP API、数据泵、WebSocket 与主题扫描拆到 `src/web/` 子模块。`RttBackend` 仍是后端唯一缝，禁止在 Web 层新增按后端 id 的业务分叉。

将面板偏好与 worker 热切换状态分开：worker 所需 Atomic 保留，面板偏好集中管理。设置请求先完整校验再提交，避免 400 响应伴随部分字段已修改。

### 4. 前端模块化

`index.html` 只保留语义结构并引用静态 CSS/JS；静态资源继续由 Rust `include_str!` 内嵌。使用原生 ES modules，不增加构建步骤。日志视图、搜索、设置、主题/弹窗与 API 各自有明确边界。

服务端偏好是业务设置唯一真源；`localStorage` 仅保留主题、字号、时间戳、自动滚动等纯显示偏好。API 错误集中处理，不再依赖大量空 `catch`。

### 5. 界面整改

- 左侧只负责数据源、探针、目标和连接；重置与电源归入设备控制。
- 日志工具条承载搜索、暂停、跟随、时间戳、HEX、标记、清空、导出。
- 发送区保留输入、发送、行尾和 HEX；定时间隔只在定时发送启用时出现。
- 主题与字号属于视图设置，不再归入“接收”。
- 侧栏可折叠；窄窗口切换为抽屉。发送选项和底栏在 1440、1024、800 三档均无溢出或逐字换行。
- 使用 `:focus-visible`、可 Tab 到达的搜索控件、合规的 combobox/listbox 与菜单语义。
- 保留四主题令牌和自定义主题能力，修正小字对比度。

## 状态与错误处理

`/api/status` 增加 `paused`，WS 快照/状态初始化后由服务端真值驱动暂停按钮。连接、暂停和设置操作失败必须可见；设置校验失败不得修改任何字段。现有 API 字段只做兼容性新增，不删除仍有消费方的字段。

## 验收

1. `cargo fmt --check`、`cargo clippy --all-targets --locked -- -D warnings`、`cargo test --locked` 全部通过。
2. `python -m pytest tests/web -q` 全部通过，新增暂停 reload 和 800px 布局回归测试。
3. 页面在 1440×900、1024×700、800×600 无横向溢出，键盘可完成搜索和主要操作。
4. 当前源码构建的 Demo 完成连接、断开、发送、暂停、清空、搜索、主题切换验证。
5. 使用用户已连接的 J-Link 做真机冒烟：枚举、连接、日志接收、发送、断开；失败时如实记录，不用 Demo 结果代替。
6. Git 差异只包含计划内源码、测试、文档和静态资源；构建垃圾删除后不重新纳入版本控制。
