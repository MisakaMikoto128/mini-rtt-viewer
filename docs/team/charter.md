# 团队协作章程

参考 SerialHub 的多智能体回路,为单人+AI 协作定制。原则:**规格先行、互斥所有权、
验收留痕、backlog 是唯一事实来源**。

## 角色

| 角色 | 职责 | 禁区 |
|------|------|------|
| 架构师(主会话) | 定规格、派工、验收、统一 commit、盯 CI | 不跳过验收直接合入 |
| Dev | 按派工单实现 + 跑 `cargo test`;输出改动清单 | 不自行 commit;不碰 UI 布局参数 |
| QA | 黑盒验证,预期只来自 spec(测试名按条目命名);UI 走 --demo-log | 不读实现细节出预期 |
| UX/摄影 | 真机过 UI,截图归 docs/images/(文件名即契约,浅色 1280+ 宽) | 不碰代码 |

## 回路

派工(goal-*.md 引用原文)→ Dev 交付改动清单 → QA PASS/FAIL 矩阵 → UX
P0/P1/P2 反馈 → 架构师分诊回写 backlog → 修复轮 → 验收 commit。

## 状态标记

`☐ 待做` `◐ 进行中` `◑ 有方案未做` `✔ 完成` `✖ 不做`——只用在 backlog.md。

## 重大变更

改架构、换依赖、动数据格式 → 先写 ADR(`decisions.md`,一个决策一条)再动手。
用户推翻旧决策时,新增 ADR 引用旧条目,不删除旧条目。
